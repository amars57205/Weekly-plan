# منصة الخطة الأسبوعية — الربط مع Google Sheets

## الفكرة
`index.html` (الواجهة) لم يعُد يخزّن البيانات في متصفحك (localStorage)، بل يرسلها
عبر الإنترنت إلى ملف `Code.gs` (خادم Google Apps Script)، وهو بدوره يقرأ/يكتب
في جدولين داخل ملف Google Sheets واحد:

| الورقة | تُخزَّن فيها |
|---|---|
| **جدول صاحب الصلاحية** | اسم المدرسة، الرقم الوزاري، الرقم السري لصاحب الصلاحية، عدد الزيارات، قوائم (الأسابيع/الصفوف/الفصول/المواد)، وجدول تسجيل المعلمين (الاسم + الرقم السري) |
| **لوحة المعلمين** | كل خطة أسبوعية يدخلها معلم (سطر واحد لكل معلم+أسبوع+صف+فصل+مادة، ويُحدَّث بدل التكرار) |

بما أن كل المستخدمين يتصلون بنفس الجدول عبر نفس الرابط، تكون البيانات مشتركة
بينهم فعلياً (وليست نسخة منفصلة لكل جهاز كما كانت سابقاً)، والقفل
`LockService` داخل الكود يمنع تعارض الكتابة عند دخول أكثر من شخص بنفس اللحظة.

## خطوات التركيب (10 دقائق)

1. **أنشئ جدول Google Sheets جديد**، وأضف فيه ورقتين بهذين الاسمين
   بالضبط (انسخ/الصق لتفادي أي فرق في المسافات):
   - `جدول صاحب الصلاحية`
   - `لوحة المعلمين`
   (احذف الورقة الافتراضية "Sheet1" إن وجدت). لا داعي لكتابة أي رؤوس بنفسك —
   الكود سينشئها تلقائياً أول مرة يعمل فيها.

2. من القائمة العلوية: **الإضافات (Extensions) ← Apps Script**.
   احذف أي كود موجود، والصق محتوى ملف `Code.gs` المرفق بالكامل.

3. في أعلى الكود، غيّر السطر:
   ```js
   const API_SECRET = 'REPLACE_WITH_YOUR_OWN_LONG_RANDOM_SECRET_2026';
   ```
   إلى نص عشوائي طويل من عندك (32 حرفاً فأكثر، أرقام وحروف).

4. **نشر (Deploy) ← New deployment**:
   - Select type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - اضغط Deploy، وامنح الأذونات المطلوبة (Authorize access).
   - انسخ الرابط الناتج (ينتهي بـ `/exec`).

5. افتح `index.html` وعدّل هذين السطرين في بداية الكود البرمجي:
   ```js
   const API_URL    = 'PASTE_YOUR_WEB_APP_URL_HERE';       // ← الصق رابط /exec هنا
   const API_SECRET = 'PASTE_THE_SAME_SECRET_AS_IN_CODE_GS'; // ← نفس السر بالضبط
   ```

6. ارفع `index.html` على GitHub (Pages) أو Google Drive كما تريد، والصفحة
   ستعمل من أي مكان طالما رابط الـ Web App يعمل.

> **ملاحظة عند أي تعديل لاحق على Code.gs:** يجب عمل **Deploy جديد** (أو
> "Manage deployments ← Edit ← New version") حتى تنعكس التعديلات على الرابط.

## نقاط الحماية المطبّقة
- **تعقيم كل المدخلات** في الخادم قبل تخزينها لمنع **Formula Injection**
  (نص يبدأ بـ `= + - @` يتحول إلى نص عادي بدل أن يُنفَّذ كصيغة في الشيت).
- **قفل الكتابة (LockService)** لمنع تعارض حفظ بيانات مستخدمين في نفس اللحظة.
- **حد أقصى لطول كل حقل** (اسم المدرسة، كلمة المرور، محتوى الخطة...) لمنع إغراق الجدول.
- **CSP وX-Frame-Options وX-Content-Type-Options** موجودة أصلاً في `<head>`
  الصفحة لمنع Clickjacking وتحديد المصادر المسموح تحميل الموارد منها.
- **مفتاح API_SECRET**: كل طلب يُرسَل يجب أن يحمل نفس المفتاح المضبوط في
  Code.gs، فيرفض الخادم أي طلب لا يحمله — هذا يمنع أي شخص "يخمّن" رابط
  Web App من العبث بالبيانات بدون معرفة المفتاح.

## حدود مهمة يجب أن تعرفها (بصراحة)
- الصفحة **HTML/JS تعمل بالكامل في متصفح المستخدم**، وأي شخص يفتح "عرض
  المصدر" (View Source) سيرى قيمة `API_SECRET` ورابط `API_URL` بوضوح.
  فهذا المفتاح **تصفية أولية ضد العبث العشوائي**، وليس حماية حقيقية بمستوى
  "تسجيل دخول". كلمة سر صاحب الصلاحية وكلمات سر المعلمين تُقارَن هي الأخرى
  داخل المتصفح، وهذا مقبول لتطبيق داخلي محدود الاستخدام (مدرسة واحدة)، لكنه
  **ليس مناسباً لبيانات حساسة فعلاً** (كأرقام هوية أو بيانات مالية).
- إن أردت حماية أقوى مستقبلاً، الحل الصحيح هو نقل التحقق من كلمات المرور
  إلى داخل `Code.gs` نفسه (بدل مقارنتها في المتصفح)، بحيث لا يغادر الرقم
  السري جهاز الخادم إطلاقاً. يمكنني تجهيز هذا التحديث إن رغبت.
- Google Apps Script لديه حدود استخدام يومية (Quota) للحسابات المجانية؛
  لمدرسة واحدة بعدد معلمين معتاد هذا غالباً كافٍ جداً.

## الملفات المرفقة
- `Code.gs` — الخادم الخلفي (يُلصَق داخل Apps Script المرتبط بالـ Sheet).
- `index.html` — نفس تصميمك وتنسيقاتك الأصلية بالكامل، مع تبديل التخزين
  المحلي بطلبات شبكة حقيقية لكل عملية (حفظ مدرسة، تسجيل معلم، حفظ خطة...).
